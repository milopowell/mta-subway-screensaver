# Subway screensaver (Swift)

The native macOS app and screensaver. The project overview, data flow, settings and known issues are in the [main README](../README.md); this file covers only the Swift code.

The app reads the four files the notebook exports in §8 of `subway_pipeline.ipynb`: the maps `../export/map_black.pdf` and `../export/map_light.pdf`, `../export/network.json` (stations, tracks, stop patterns) and `../export/schedule.json` (the timetable, for lines without live data). They are copied into the apps and the screensaver at build time, so **rebuild (or reinstall) after re-running the export**.

## Layout

| Folder | Built into | Contents |
|---|---|---|
| `Shared/` | all three | Everything below |
| `PreviewApp/` | SubwayPreview | A normal Mac app that shows `SubwayView` in a window, for development, plus the command-line test options |
| `Sandbox/` | SubwaySandbox | A separate app for sending trains by hand and trying out new features: no live data, no saved settings (see below) |
| `Saver/` | SubwaySaver | `SubwaySaverView`, the `.saver` entry point: hosts `SubwayView`, provides the Options sheet, stops on `willstop`; `thumbnail.png` for System Settings |
| `../export/` | all three | The notebook's exported maps, network data and timetable (bundled as resources) |

The preview app's and the sandbox's icons are in `Assets.xcassets` in their folders, drawn by `../tools/make_icons.swift` (the preview app's "night lines": red, blue and orange lines on black with one white train; the sandbox's "blueprint": white track on a blue drafting grid). They are original artwork, so they are kept in the repository; to change them, edit and run the script, then rebuild.

The project uses Xcode's folder-synced groups, so a file added to one of these folders joins the matching target(s) automatically. `SubwaySaver.xcodeproj` is generated by `../tools/gen_xcodeproj.py`; regenerate it rather than editing it by hand.

### Shared code

| File | Role |
|---|---|
| `SubwayView.swift` | Lays out the map panels and the next-train board (split or close-up layout). Downloads feeds every 30 s and updates trains every second; lines without live data run from the timetable, and the corner note says which |
| `MapPanel.swift` | One view of the map: the map bitmap, its trains and an optional dashed outline (the split layout's full map, showing the magnified area) |
| `MapDocument.swift` | Renders a region of the map PDF to a bitmap |
| `Viewport.swift` | Fits a map region to a panel's shape |
| `SubwayNetwork.swift` | Reads `network.json` |
| `FeedClient.swift` | Downloads and decodes the 8 live feeds in parallel; `FeedCache` holds each feed's last good download when one fails; `FeedHub` shares one download loop among all views |
| `gtfs-realtime.pb.swift` | Generated feed decoder (do not edit) |
| `Locator.swift` | Places trains: an exact port of the notebook's `locate_from_export` (hops follow the exported `hop_paths`, and rerouted trains another line's track), plus each train's timeline of hops (`legs`), where each waiting train will leave toward, and which lines a train passes under |
| `MotionPlanner.swift` | Turns timelines into motion: when each train stands, glides, waits, catches up or fades elsewhere |
| `TrainLayers.swift` | Draws the trains (white dots when moving; route bullets pointing the way they leave, breathing, when waiting or parked) and runs the glide animations (Core Animation) |
| `TripHistory.swift` | Records when each train actually reached and left each station, from successive downloads |
| `TimeLapse.swift` | Replays that history at 20 times speed in a loop (same commands as MotionPlanner): a testing tool |
| `Schedule.swift` | The MTA timetable (`schedule.json`): the trains that should be running now, described like live trips, for lines without live data; `Trip.identity`, the trip code a live train and its scheduled twin share |
| `Polyline.swift` | Geometry along a track line |
| `NextTrains.swift` | The next-train board: arrivals per home station, uptown and downtown |
| `StationPicker.swift` | The home-station picker: your stations (reorder, remove), search, browse by line, stations by borough (preview app only: a screensaver cannot be clicked) |
| `RouteSymbols.swift` | Route symbols (colored circles, diamonds for express variants), shared by the picker, the next-train board and the waiting trains' bullets |
| `SubwaySettings.swift` | Saved choices: home stations (up to 4), layout, magnification, appearance, train board style and tint |
| `Theme.swift` | Dark and light: which map to show and the colors of the dots, board, cards and notes |
| `AppearanceOptions.swift` | The appearance choices in the screensaver's Options sheet: dark or light, the train board's glass and its tint |
| `BuildInfo.swift` | The commit and date an installed copy was built from, for the About window (stamped by `../tools/install_apps.sh`) |

## Building and running

Build by **scheme** so the SwiftProtobuf package is built too (a `-target` build fails). Use Release to measure performance.

```bash
cd ~/mta-screensaver/swift && xcodebuild -project SubwaySaver.xcodeproj -scheme SubwayPreview -configuration Release -destination 'platform=macOS' -derivedDataPath build/DerivedData -clonedSourcePackagesDirPath build/SourcePackages build
```

```bash
open ~/mta-screensaver/swift/build/DerivedData/Build/Products/Release/SubwayPreview.app
```

In Xcode: open `SubwaySaver.xcodeproj`, pick the SubwayPreview scheme and press Command-R.

Preview app options (run the executable inside the app directly):

- `--fullscreen`: start in full screen (Control-Command-F toggles it, Command-Q quits)
- `--snapshot out.png [--width 1512 --height 982]`: render the view to a PNG and quit, without a window
- `--home ID,ID`, `--layout split|closeUp` and `--magnification M`: home stations, layout and magnification for a snapshot only
- `--appearance dark|light|system|timeOfDay` and `--board glass|clearGlass|solid`: appearance and train board style for a snapshot only (the glass itself isn't captured off screen; the board's own drawing is)
- `--dump-placements out.json`: write every trip's placement (feed, trip_id, x, y, how) and quit
- train data for those two: `--live` (download now), or `--feeds-dir DIR --now UNIXTIME` (saved feeds `DIR/<feed>.pb`)
- `--plan-report [--seconds 90]`: run the motion planner on live data and report how trains move
- `--time-lapse`: force the time-lapse; `--time-lapse-after S` starts it after S seconds of history instead of 5 minutes
- `--offline`: no live data from the start, so every line runs from the timetable (in the window, or in `--snapshot` and `--dump-placements`, where it also supplies the train data)
- `--handoff-report [--seconds 90]`: start the motion planner on the timetable, switch it to live data, and report how the scheduled trains hand over to their live twins
- `--path-report out`: check the track every hop follows; writes `out.png`
- `--path-audit [--seconds 180]`: run live motion and report off-track glides, jumps, fades, short sideways moves (with what the feed said about each train and why the planner moved it), rerouted hops and slow glides
- `--picker-snapshot out.png [--home IDs --line ROUTE]`: render the home-station picker
- `--time-lapse-report [--record 420 --seconds 60]`: record live history, replay it, and check the replay is smooth
- `--timing-report [--seconds 180]`: compare the dots' station arrivals and departures with the real trains
- `--simulate-outage FEED[,FEED...]` or `--simulate-outage all`: treat those feeds as failed after the first download (in the window, in `--plan-report`, and in `--snapshot`, where `--outage-age S` sets how long ago they failed: over 300 s, their lines run from the timetable)

`build/` holds build output and can be deleted at any time.

## Sandbox

SubwaySandbox is a separate app for playing with train motion. It never downloads anything and shares no settings with the preview app or the screensaver; it shares only the code in `Shared/`, so a change to the motion or drawing code shows up here as it will in the screensaver. A feature can also be tried in `Sandbox/` alone first, where nothing else sees it.

```bash
cd ~/mta-screensaver/swift && xcodebuild -project SubwaySaver.xcodeproj -scheme SubwaySandbox -configuration Release -destination 'platform=macOS' -derivedDataPath build/DerivedData -clonedSourcePackagesDirPath build/SourcePackages build
```

```bash
open ~/mta-screensaver/swift/build/DerivedData/Build/Products/Release/SubwaySandbox.app
```

- **Send a train:** pick a route and two of its stations, and a pace (as scheduled, or 2 or 4 times faster). The train waits 15 s, then runs stop by stop on the route's timetable. Send 10 random sends trains on random routes.
- **Trains:** Delay 30 s and Jump ahead 60 s change a train's timetable, as when a real train runs late or the data catches up with it; the change arrives with the next update, so you can watch how the motion corrects. Remove takes a train out of the data.
- **View:** magnification 1 to 10 times; click the map to center it there.
- **Feed:** updates every 30 s like the live feed, or every second.
- **Dark map / Light map** switches the sandbox's map.

`SimulatedFeed.swift` turns the trains you send into the same trip records the MTA feeds produce; `SandboxView.swift` runs them through the app's own `MotionPlanner` and `MapPanel`. Two test options (run the executable inside the app directly): `--check` runs the pretend feed on a simulated clock and prints every glide of a 1 train from 59 St-Columbus Circle to 14 St, then totals for 10 random trains; `--snapshot out.png` renders the window after sending that train.

## Installing the screensaver

`zsh ../tools/install_saver.sh` builds and installs it in `~/Library/Screen Savers` (and `zsh ../tools/install_apps.sh` installs the preview app and the sandbox in `~/Applications`, stamped with the commit they were built from: `Shared/BuildInfo.swift` shows it in their About windows); `../tools/test_saver.swift` tests the built bundle without installing it (see the main README).

## Regenerating the feed decoder

`Shared/gtfs-realtime.pb.swift` is generated from the same schema the notebook's Python bindings use, saved as `../tools/gtfs-realtime.desc`. Install the tools with `brew install protobuf swift-protobuf`, then run `protoc` with `--swift_out`. The SwiftProtobuf package version in the project must be at least the `protoc-gen-swift` version that generated the file (currently 1.39.0).

## Sharing

The bundled map is MTA artwork, for personal use only. Do not share the built app or screensaver.
